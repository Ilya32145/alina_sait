Что хорошо
1) Семантика (<header>, <main>, <nav>, <section>)
2) Функция clamp() для адаптивной типографики
3) Grid и Flexbox

На что стоит обратить внимание. Смотрю с точки зрения коммерческой разработки, так как смотрят на ревью на работе 

1) Отсутствие <h1>: На странице нет главного заголовка. Теги <p class="zagolovok"> и <p class="sip"> должны быть заголовками (от <h1> до <h3> в зависимости от иерархии). Это критично для SEO
2) Использование <ol>: Тег <ol> (ordered list) предназначен для нумерованных списков. Ты используешь его для навигации, карточек мест, иконок и футера. Там, где порядок не важен, нужно использовать <ul> (unordered list). А для блока с иконками лучше вообще использовать <div> или семантические теги <article>
3) Элементы, инициирующие действие (например, отправку формы или открытие модалки), должны быть <button>, а не <a>. У тебя форма подписки сабмитится через <a href="#" class="button20">Enter</a> - это не будет работать без JS и нарушает стандарты. Используй <button type="submit">
4) Отсутствие <footer>: Подвал сайта обернут в <section class="konec">. Для подвала есть специальный тег <footer>
5) Инпут для email не имеет привязки к <label>. Добавь id инпуту и свяжи его с лейблом через for="id" или оберни текст и инпут в тег <label>
6) Классы вроде coala, ludi, gora, konec, pochti, voda - это недопустимо в коммерческом коде. Весь код должен быть на английском языке. coala -> hero-image, ludi -> people, konec -> footer, voda -> likes-text
7) Классы text, text2, sip, sixseven, button15, button20 ни о чем не говорят разработчику. Имена классов должны отражать суть элемента, а не его положение на странице
8) Дублирование стилей кнопок: У тебя созданы классы .button, .button2, .button10, .button15, .button20, которые делают почти одно и то же
Решение: Создай один базовый класс .btn с основными стилями (отступы, шрифт, скругление) и модификаторы для разных состояний или цветов: .btn--primary, .btn--secondary
9) Хардкодить значения цвета orange по всему файлу — плохая практика. Если дизайнер решит сделать кнопку красной, тебе придется менять код в 10 местах. Объяви переменные в :root и используй их
:root {
    --color-primary: #FFA500; /* или любой другой оранжевый */
    --color-text: #ffffff;
    --bg-dark: rgba(0, 0, 0, 0.945);
    --container-width: min(1400px, 92%);
}
10) Конфликт ширин: В классе .gora ты пишешь width: min(1400px, 92%);, а строчкой ниже width: 60%;. Второе свойство перезаписывает первое. Это может привести к непредвиденным багам. Убирай лишнее.
11) Магические числа: Огромные отступы вроде margin-top: 200px; обычно говорят о том, что верстка "собирается на костылях". Используй пропорциональные отступы, например через переменные или clamp(), чтобы они масштабировались
12) Секции ради секций: У тебя есть <section id="gradient">, внутри которого лежат <section class="hero">, <section class="popular"> и т.д. Обертка <section id="gradient"> используется исключительно для фона. Для таких вещей лучше использовать <div> или применять градиент к псевдоэлементу (::before) body или <main>.
13) Незакрытые теги / лишние теги: Перед <section id="gradient2"> есть лишний закрывающий тег </section>. Форматирование кода (например, через Prettier в VS Code) поможет избежать таких ошибок
