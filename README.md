### На что стоит обратить внимание

#### 1. Семантика и доступность (HTML)
* **Отсутствие `<h1>`:** На странице нет главного заголовка. Теги `<p class="zagolovok">` и `<p class="sip">` должны быть заголовками (от `<h1>` до `<h3>` в зависимости от иерархии). Это критично для SEO.
* **Неправильное использование `<ol>`:** Тег `<ol>` (ordered list) предназначен для нумерованных списков. Он используется для навигации, карточек мест, иконок и футера. Там, где порядок не важен, нужно использовать `<ul>` (unordered list). Для блока с иконками лучше вообще использовать `<div>` или семантические теги `<article>`.
* **Кнопки vs Ссылки:** Элементы, инициирующие действие (например, отправку формы), должны быть `<button>`, а не `<a>`. Форма подписки сабмитится через `<a href="#" class="button20">Enter</a>` — это не будет работать без JS и нарушает стандарты. Используй `<button type="submit">`.
* **Отсутствие `<footer>`:** Подвал сайта обернут в `<section class="konec">`. Для подвала есть специальный тег `<footer>`.
* **Доступность форм:** Инпут для email не имеет привязки к `<label>`. Добавь `id` инпуту и свяжи его с лейблом через `for="id"`, либо оберни текст и инпут в тег `<label>`.

#### 2. Именование классов
* **Транслит в классах:** Классы вроде `coala`, `ludi`, `gora`, `konec`, `pochti`, `voda` — недопустимы в коммерческом коде. Весь код должен быть на английском языке (например: `coala` → `hero-image`, `ludi` → `people`, `konec` → `footer`, `voda` → `likes-text`).
* **Неинформативные названия:** Классы `text`, `text2`, `sip`, `sixseven`, `button15`, `button20` ни о чем не говорят разработчику. Имена классов должны отражать суть элемента, а не его положение на странице.

#### 3. Архитектура CSS
* **Дублирование стилей кнопок:** Созданы классы `.button`, `.button2`, `.button10`, `.button15`, `.button20`, которые делают почти одно и то же.
  * *Решение:* Создай один базовый класс `.btn` с основными стилями (отступы, шрифт, скругление) и модификаторы для разных состояний/цветов: `.btn--primary`, `.btn--secondary`.
* **Хардкод цветов:** Использовать значение `orange` по всему файлу — плохая практика. Если дизайнер решит сделать кнопку красной, придется менять код в 10 местах. Объяви переменные в `:root` и используй их:
  ```css
  :root {
      --color-primary: #FFA500; /* или любой другой оранжевый */
      --color-text: #ffffff;
      --bg-dark: rgba(0, 0, 0, 0.945);
      --container-width: min(1400px, 92%);
  }
  ```
* **Конфликт ширин:** В классе `.gora` написано `width: min(1400px, 92%);`, а строчкой ниже `width: 60%;`. Второе свойство перезаписывает первое, что может привести к непредвиденным багам. Убирай лишнее.
* **Магические числа:** Огромные отступы вроде `margin-top: 200px;` обычно говорят о том, что верстка "собирается на костылях". Используй пропорциональные отступы, например через переменные или `clamp()`, чтобы они масштабировались.

#### 4. Структура документа
* **Секции ради секций:** Есть `<section id="gradient">`, внутри которого лежат другие секции. Обертка используется исключительно для фона. Для таких вещей лучше использовать `<div>` или применять градиент к псевдоэлементу (`::before`) `body` или `<main>`.
* **Лишние теги:** Перед `<section id="gradient2">` есть лишний закрывающий тег `</section>`. Настройка автоформатирования кода (например, через Prettier в VS Code) поможет избегать таких ошибок.
